# VeriFact

VeriFact is a long-form clinical text fact-checker that verifies patient-specific text against the
patient's electronic health record (EHR). It decomposes text into propositions and combines
retrieval-augmented generation with an LLM-as-a-judge to classify each proposition as `Supported`,
`Not Supported`, or `Not Addressed`.

- **Publication:** [Verifying Facts in Patient Care Documents Generated by Large Language Models
  Using Electronic Health Records](https://ai.nejm.org/doi/full/10.1056/AIdbp2500418)
- **Dataset:** [MIMIC-III-Ext-VeriFact-BHC v1.1.0](https://physionet.org/content/mimic-iii-ext-verifact-bhc/1.1.0/)

VeriFact-BHC contains human- and LLM-written Brief Hospital Course narratives, sentence and
atomic-claim propositions, human annotations, released VeriFact verdicts, and the reference EHRs
for 100 patients derived from MIMIC-III Clinical Database v1.4.

## Python environment

The project uses `uv` and a workspace of local packages:

```sh
uv sync --all-packages --frozen
```

Create a machine-local configuration before running services or inference:

```sh
cp .env.example .env
```

Edit `.env` to set local paths, GPU assignments, `HF_HOME`, and a Hugging Face read token. The
file is ignored by Git. Never commit credentials. Model-specific, credential-free overlays are in
`configs/inference/`.

## Reproducing the study

The public repository has three distinct workflows:

- `scripts/evaluate/replay_physionet_v1_1_0.py` repeats judge inference from the exact propositions
  and retrieved contexts released in PhysioNet v1.1.0. This is the preferred inference
  reproduction path and does not rebuild retrieval.
- `scripts/analysis_verifact/` loads the v1.1.0 Parquet/CSV release through a compatibility adapter
  and reproduces saved-verdict analyses without model services or a vector database.
- `scripts/evaluate/run_verifact.py` reruns the full retrieval-and-judging pipeline and requires a
  populated Qdrant database, embedding and reranking services, Redis/RQ, and model inference.

See [`scripts/evaluate/README.md`](scripts/evaluate/README.md) for exact replay and inference
commands, [`scripts/analysis_verifact/README.md`](scripts/analysis_verifact/README.md) for analysis,
and [`scripts/dataset/README.md`](scripts/dataset/README.md) for dataset/vector-database creation.

## Local services

Services are defined in `docker-compose.yml`:

1. vLLM main judge and auxiliary structured-output model;
2. BGE-M3 embedding and reranking APIs;
3. Qdrant;
4. Redis and RQ Dashboard;
5. Traefik;
6. Prometheus and Grafana.

Start a manuscript judge by overlaying its profile after `.env`:

```sh
# Non-reasoning model
docker compose --env-file .env \
  --env-file configs/inference/gemma-3-12b.env \
  up -d traefik llm-main

# Reasoning model (adds the auxiliary structured-output model)
docker compose --env-file .env \
  --env-file configs/inference/r1-70b.env \
  up -d traefik llm-main llm-aux
```

The supplied profiles cover Llama 3.1 8B/70B, DeepSeek-R1-Distill-Llama 8B/70B, Gemma 3
12B/27B, Qwen 3 30B-A3B Instruct/Thinking, and Qwen 3 32B. Hardware requirements differ
substantially; adjust only the machine-specific GPU and memory settings in `.env`.

For the full retrieval path, launch the required data services as well:

```sh
docker compose --env-file .env up -d traefik qdrant redis rq-dashboard
docker compose --env-file .env up -d embed3 rerank3
```

Service endpoints are routed through Traefik. Prometheus/Grafana monitoring is documented in
`services/vllm/monitoring/README.md`.
